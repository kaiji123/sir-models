# Diagram to R
**Live demo:** [compartmodels.com](https://compartmodels.com)
Draw a compartmental epidemic model (SIR, SEIR, vector-borne, …) as a box-and-arrow diagram and get
ready-to-run **R / deSolve** code. Generation is **deterministic**: the same diagram always produces
byte-identical R code (no timestamps, no randomness; order comes only from the model's lists).

```
npm install
npm run dev        # editor at http://localhost:4321, model library at /library/
npm test           # generator tests + runs every model in R (skipped if Rscript/deSolve missing)
npm run build      # static site in dist/ — deploy to Netlify, Vercel, Cloudflare Pages, GitHub Pages…
```

## How a diagram becomes R code

| Diagram element | R code |
| --- | --- |
| Compartment `S` (initial value `990`) | state variable `S`, equation `dS <- …`, entry in `state` |
| Arrow `S → I` labelled `lam` (per-capita) | `- lam * S` in `dS`, `+ lam * S` in `dI` |
| Arrow from outside `→ S` labelled `mu * N` (absolute) | `+ mu * N` in `dS` (births, immigration) |
| Arrow `I →` outside labelled `mu` | `- mu * I` in `dI` (deaths, emigration) |
| Parameter `gamma = 1 / 7` | entry in `parameters <- c(...)` |
| Variable `lam = beta * I / N` | computed each time step, in dependency order |
| Flow/variable marked as output | returned as extra columns of `out` (e.g. incidence) |

Total population `N` is the sum of compartments marked "counts towards total population"
(untick it for deaths, or for an environmental reservoir).

Expressions are validated before code is produced: unknown names, syntax errors, R reserved
names (`F`, `T`, `c`, …), name clashes, dependency cycles and per-capita inflows are reported
and can be clicked to jump to the problem.

## Layout

```
src/lib/generator.js   model JSON → R code (pure; shared by web app, CLI and tests)
src/lib/library.js     hand-written models + imported research models
src/lib/library-research.js  generated by cli/import-research.mjs
src/lib/search.js      library search (shared by editor, /library/ page and tests)
src/lib/editor.js      the diagram editor (browser only)
src/pages/             Astro pages: editor, /library/, /examples/<id>.R|.json
cli/generate.mjs       node cli/generate.mjs model.json [out.R]
cli/build-examples.mjs regenerates examples/ (golden files used by the tests)
examples/              every library model as .json + generated .R
test/                  node:test suites; test/r/ holds the R-side checks
```

The search box on the editor (press `/`) and on `/library/` finds models by name, disease,
compartment (`has:E`), category (`cat:vector`), reference or parameter.

**Provenance.** The 85 models from the literature review (88 found, 3 duplicates dropped) were imported from
`research_notes/` by `cli/import-research.mjs`. Every parameter description carries a tag:
`[verified]` (checked against the cited paper), `[recalled]` or `[illustrative]`; each
description says how many values were checked. Most values are illustrative, so treat these as
structurally faithful starting points and check values against the cited source before use.
The full catalogue with sources is in `reports/`.

To add a model by hand, add a `def({...})` entry to `src/lib/library.js`; to re-import the
research notes, run `node cli/import-research.mjs`. Then run `npm run examples && npm test`.

## Verification

`test/r.test.mjs` checks that the generated Hepatitis E model reproduces the original
hand-written practical script exactly (max difference 0) and that all 118 library models solve
in R with finite, non-negative compartments.
